# معماری قابل گسترش قطعه‌یار

برنامه یک وب‌سرور Python/Flask روی ویندوز مرکزی، دیتابیس SQLite محلی و رابط فارسی مرورگر دارد. فایل‌های داده و رمزها از کد جدا هستند. هر تغییر ساختار دیتابیس یک migration جدید دارد.

| بخش | مسئولیت |
| --- | --- |
| `auth.py`, `users.py` | نشست، کاربران و نقش‌ها |
| `catalog.py`, `search.py` | کالا، قیمت و جستجو |
| `invoices.py`, `returns.py`, `purchase_returns.py` | خرید، فروش، برگشت، موجودی و تسویه |
| `checks.py`, `opening_balances.py` | چک و ماندهٔ افتتاحیه |
| `reports.py`, `calendar.py` | صندوق، بانک، نمودارها، سود و زیان و نمایش تقویم |
| `settings.py`, `updates.py` | تنظیمات و انتشار نسخه |
| `backup.py`, `transfer.py`, `db.py`, `migrations/` | بکاپ، ورود دادهٔ حسابداری، اتصال و مهاجرت داده |

مبلغ‌های عملیاتی عدد صحیح ریال هستند. دادهٔ انتقالی نیز پس از تبدیل واحد به ریال ذخیره می‌شود. مهاجرت ۰۰۹ مقادیر عملیاتی قدیمی را از تومان به ریال تبدیل می‌کند. پرداخت جدید به یک حساب مالی مشخص وصل می‌شود؛ ماندهٔ ابتدای دوره در جمع حساب‌ها منظور می‌شود. فاکتورهای قطعی تغییر نمی‌کنند و برگشت با سند مستقل ثبت می‌شود.

دیتابیس SQLite با WAL روی همان ویندوز مرکزی قرار دارد؛ فایل آن نباید روی پوشهٔ اشتراکی شبکه باشد. بکاپ با API خود SQLite ساخته و با SHA256 و `integrity_check` بررسی می‌شود. نصب تازه دادهٔ فروشگاهی ندارد. دادهٔ نصب قبلی با بکاپ برنامه بازگردانی می‌شود؛ دادهٔ سامانه‌های دیگر از بستهٔ انتقال استاندارد یا مبدل اختصاصی روی نصب خالی وارد می‌شود.

مسیرهای JSON جدید زیر `/api/v1/` قرار می‌گیرند. لایه‌های مستقل برنامه امکان افزودن بارکد، چند شعبه، چاپ فاکتور، دفتر کل دوطرفه و API موبایل را در نسخه‌های بعدی فراهم می‌کنند.
